getokui

A Claude Code plugin that gives AI a taste library — a curated collection of design references — so AI-generated UIs stop looking template-y.

Status Design — ready for review Deadline July 31, 2026 Architecture Skill-only · 2 repos Pattern reference ajisss/design-agent
Why this exists
1

Problem → Solution

Asked to build UI from scratch, AI often produces plain, generic results ("AI slop") because it's guessing from nothing. Tools like Lovable/v0 are good because they have a reference collection. getokui gives Claude that collection — local & curated.

😐 Without getokui

Claude guesses a design from scratch → template-y result. The developer still has to rework it manually for every page. Time-consuming, tedious, repetitive.

✨ With getokui

Claude reads a library of good references → borrows + adapts. The reference is already good, so the result is too. The repetitive "build good UI from scratch" work gets cut down.

Adaptation rule · from design-agent
7

Take the style, not the content

So the result genuinely "belongs to the user", not a paste-up. A lesson borrowed from ajisss/design-agent.

✓ May be taken from the template

  • Colors, spacing, radius, shadow, typography, motion
  • Layout grid & component shapes (card, button)
  • Section types (hero, features, pricing)
  • Structural patterns

✕ Must NOT be copied

  • The template's original headlines / copy / product descriptions
  • Feature names & business-specific wording
  • Third-party brand assets (logos, photos, illustrations)
  • → use clear placeholders or ask the user

Learning from what already works
9

Adapted from ajisss/design-agent

getokui borrows its discipline (pipeline, checkpoint, style-vs-content), not its web-search mechanism. Core difference: design-agent searches for live references from the web each request; getokui uses a curated local library — offline & demo-safe.

✅ What we took

✓ Multi-skill pipeline — simplified to setup → pick → build
✓ Checkpoint = hard stop — agent stops, user decides
✓ Separate style vs content — don't copy the template's copy
✓ Battle-tested marketplace install instructions
✓ Honest about match quality — don't force a weak candidate
✓ Copyright note — structural patterns, not assets

➖ What we skipped (overkill for one day)

➖ Per-project registry (.design/registry) — getokui's library is global, no per-project state needed
➖ PostToolUse hooks (validate-tokens) — adds crash risk at demo
➖ QA token-compare + visual diff — Playwright is used only to generate thumbnails, not runtime QA
➖ Full confidence markers — "honest about match" is enough, without a scoring system
